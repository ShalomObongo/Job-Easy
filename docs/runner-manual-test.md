# Runner Manual Test Checklist (Skyvern Local)

This checklist validates the current Skyvern-local runner behavior end-to-end.

## Preconditions

- Local Skyvern service running (`./scripts/start_skyvern_local.sh` recommended).
- `.env` configured with at least:
  - `RUNNER_BACKEND=skyvern_local`
  - `RUNNER_SKYVERN_BASE_URL=http://localhost:8000`
  - `RUNNER_SKYVERN_ENFORCE_LOCAL=true`
  - `RUNNER_SKYVERN_MAX_WAIT_SECONDS=1800`
- Profile available at `profiles/profile.yaml`.
- Resume and cover letter files available (or generated by `single` mode).

## Test 1: Local enforcement guard

1. Set:
   - `RUNNER_SKYVERN_BASE_URL=https://api.skyvern.com`
   - `RUNNER_SKYVERN_ENFORCE_LOCAL=true`
2. Run:
   - `python -m src apply "https://example.com/jobs/123" --resume ./resume.pdf`
3. Expect:
   - immediate failure with local-enforcement diagnostic
   - `application_result.json` written

## Test 2: Health-check fail-fast

1. Set:
   - `RUNNER_SKYVERN_BASE_URL=http://127.0.0.1:65534`
2. Run:
   - `python -m src apply "https://example.com/jobs/123" --resume ./resume.pdf`
3. Expect:
   - failure with health endpoint diagnostic
   - no indefinite hang
   - `application_result.json` written

## Test 3: Upload routing disambiguation

1. Run on a form with separate Resume and Cover upload controls.
2. Use both files:
   - `--resume ...`
   - `--cover-letter ...`
3. Expect:
   - resume file uploaded only to Resume/CV field
   - cover-letter PDF uploaded only to explicit cover-letter/supporting-document field
   - no cross-upload (cover in resume field, or resume in cover field)

## Test 4: Cover-letter text field behavior

1. Run on a form that requests written cover letter text in a textarea/editor.
2. Enable context-rich answering:
   - `--yolo` + profile + JD context
3. Expect:
   - tailored cover letter content typed into text field
   - no file upload used to satisfy text-only cover-letter question

## Test 5: Required-field sweep before completion

1. Run on a large Greenhouse form with many required dropdowns/consents/demographics.
2. Expect:
   - runner does not stop right after identity fields + uploads
   - runner continues through required dropdown chain
   - `complete`/submit action appears only after required fields are resolved

## Test 6: Long-form timeout behavior

1. Run a long real-world application (`single` mode recommended).
2. Expect:
   - run completes within default `RUNNER_SKYVERN_MAX_WAIT_SECONDS=1800`
   - no early CLI timeout while Skyvern run is still active
3. If timeout occurs:
   - inspect `skyvern_execution.json`
   - raise `RUNNER_SKYVERN_MAX_WAIT_SECONDS` and retry

## Test 7: End-to-end single mode

1. Run:
   - `python -m src single "<JOB_POSTING_URL>" --yolo --yes --auto-submit`
2. Expect:
   - duplicate checks still enforced
   - fit + document gates still enforced (or explicitly auto-approved by flags)
   - runner executes via Skyvern local backend
   - final status in `application_result.json` reflects terminal state (`submitted`, `blocked`, etc.)

## Safety Checks

- No CAPTCHA/OTP bypass automation.
- Auto-submit only when prerequisites are enabled.
- Prohibited domains still blocked (`PROHIBITED_DOMAINS`).
- Allowed domains appended to `ALLOWLIST_LOG_PATH`.
- Artifacts present:
  - `application_result.json`
  - `conversation.jsonl`
  - `skyvern_execution.json`
  - `skyvern_artifacts.json` when available
